# راهنمای راه‌اندازی «بانک محتوای تربیتی صالحات»

این راهنما برای کسی نوشته شده که برنامه‌نویس نیست. همهٔ کارها از طریق وب‌سایت‌های GitHub و Supabase و با کلیک و کپی‌/پیست انجام می‌شود. زمان تقریبی: ۳۰ تا ۴۵ دقیقه.

---

## ۱. چه فایل‌هایی ساخته شده؟

```
index.html                  صفحهٔ اصلی و پوستهٔ سایت
css/style.css               ظاهر سایت (رنگ‌ها، گل‌ها، موبایل)
js/config.js                ← تنها فایلی که باید دو مقدار در آن وارد کنید
js/api.js                   ارتباط با Supabase
js/main.js                  منو، مسیریابی صفحه‌ها
js/views-public.js          صفحهٔ اصلی، کتابخانه، موضوعات، جست‌وجو، نمایش محتوا، بازخورد
js/views-auth.js            ورود، ثبت‌نام، بازیابی رمز
js/views-editor.js          افزودن/ویرایش محتوا، آپلود فایل
js/views-admin.js           پنل مدیریت
js/util.js                  ابزارهای کمکی و امن‌سازی متن
supabase/01_schema.sql      ساخت جدول‌ها، امنیت (RLS)، ذخیره‌سازی فایل، دسته‌های اولیه
supabase/02_first_admin.sql ساخت نخستین مدیر (امن)
supabase/03_subcategory_by_educators.sql اجازهٔ ساخت زیرشاخه برای مربی تأییدشده
supabase/04_delete_permissions.sql مجوز حذف زیرشاخه (مدیر و مربیِ سازندهٔ زیرشاخهٔ خالی)
supabase/05_library_separation.sql جدا کردن کتابخانه از موضوعات
assets/logo-salehat.png لوگوی صالحات (صفحهٔ اصلی)
docs/                       همین راهنما
```

هیچ محتوای نمونه‌ای در دیتابیس گذاشته نشده است. فقط ۱۰ دستهٔ اصلی (بدون زیرمجموعه) ساخته می‌شود.

---

## ۲. ساخت پروژه در Supabase

1. به supabase.com بروید و وارد شوید (یا ثبت‌نام کنید).
2. **New project** را بزنید. نام دلخواه، یک رمز قوی برای دیتابیس (آن را در جای امن ذخیره کنید) و نزدیک‌ترین منطقه (Region) را انتخاب کنید. چند دقیقه صبر کنید تا آماده شود.
3. از منوی کنار: **SQL Editor** ← **New query**.
4. محتوای کامل فایل `supabase/01_schema.sql` را کپی و آن‌جا پیست کنید و **Run** بزنید. باید پیام موفقیت ببینید. (اجرای دوباره‌اش هم بی‌خطر است.)
5. برای اطمینان: **Table Editor** را باز کنید؛ جدول‌هایی مثل `categories` و `contents` را می‌بینید و در `categories` باید ۱۰ دسته باشد. در **Storage** باید باکت خصوصی `content-files` وجود داشته باشد.

### گرفتن دو مقدار اتصال
1. **Project Settings** ← **API** (در بعضی نسخه‌ها: **API Keys**).
2. مقدار **Project URL** را کپی کنید (مثلاً `https://abcd.supabase.co`).
3. کلید **anon / publishable** را کپی کنید.

> ⚠️ کلید **service_role** را هرگز در سایت یا GitHub قرار ندهید. به آن نیازی نیست. دو مقدار بالا «عمومی» هستند و گذاشتن‌شان در GitHub مشکل امنیتی ایجاد نمی‌کند؛ امنیت واقعی با سیاست‌های دیتابیس تأمین شده است.

### تنظیمات احراز هویت
در **Authentication**:
- **URL Configuration**: بعد از مرحلهٔ ۴ این راهنما و فعال‌شدن GitHub Pages، آدرس سایت را اینجا وارد کنید:
  - **Site URL**: `https://نام-کاربری-شما.github.io/نام-مخزن/`
  - **Redirect URLs**: همان آدرس را اضافه کنید (و یک بار هم با `/**` در انتها).
  بدون این مرحله، لینک‌های ایمیلِ تأیید و بازیابی رمز به آدرس اشتباه می‌روند.
- **Sign In / Providers ← Email**: «Confirm email» را می‌توانید روشن بگذارید (توصیه می‌شود). حداقل طول رمز را روی ۸ بگذارید.
- ایمیل‌های پیش‌فرض Supabase محدودیت ارسال کمی دارند. اگر مربیان زیادی ثبت‌نام می‌کنند، در **Authentication ← SMTP Settings** یک سرویس ایمیل خودتان وصل کنید.

## ۳. گذاشتن پروژه در GitHub

1. در github.com حساب بسازید و **New repository** بزنید. نام مثلاً `salehat`، نوع **Public**.
2. در صفحهٔ مخزن: **uploading an existing file** را بزنید.
3. **همهٔ فایل‌ها و پوشه‌های** این پروژه (`index.html`، `css`، `js`، `supabase`، `docs`، …) را بکشید و رها کنید. **Commit changes** بزنید.
   - اگر آپلود پوشه‌ها با مرورگر مشکل داشت، از برنامهٔ GitHub Desktop استفاده کنید.
4. فایل `js/config.js` را در GitHub باز کنید ← آیکون مداد (Edit) ← دو مقدار `PASTE_...` را با Project URL و کلید anon جایگزین کنید (داخل گیومه‌ها بماند) ← **Commit changes**.

## ۴. فعال‌کردن GitHub Pages
1. در مخزن: **Settings** ← **Pages**.
2. در **Build and deployment**: Source = **Deploy from a branch**؛ Branch = **main** و پوشهٔ **/ (root)** ← **Save**.
3. بعد از ۱ تا ۳ دقیقه، آدرس سایت بالای همان صفحه نوشته می‌شود: `https://نام-کاربری.github.io/salehat/`
4. حالا به Supabase برگردید و آدرس را در **URL Configuration** وارد کنید (بخش ۲).

## ۵. ساخت نخستین مدیر (امن)

ثبت‌نام اول به‌طور خودکار مدیر نمی‌شود. مدیر را فقط شما، از داخل داشبورد Supabase، تعیین می‌کنید:

1. در خود سایت روی **ثبت‌نام مربی** بزنید و با ایمیل و رمز خودتان ثبت‌نام کنید. اگر ایمیل تأیید آمد، لینکش را باز کنید.
2. در Supabase: **SQL Editor** ← **New query**. محتوای `supabase/02_first_admin.sql` را پیست کنید.
3. در همان متن، عبارت `your-email@example.com` را با ایمیل خودتان عوض کنید ← **Run**.
4. در خروجی باید ایمیل شما با نقش `admin` و وضعیت `approved` دیده شود.
5. در سایت یک‌بار خارج و دوباره وارد شوید؛ گزینهٔ «پنل مدیریت» ظاهر می‌شود.

مدیران بعدی را از **پنل مدیریت ← کاربران** با تغییر نقش می‌سازید. سیستم اجازه نمی‌دهد آخرین مدیر فعال را غیرفعال یا تنزل دهید.

## ۶. آزمایش اولیهٔ سایت (فهرست بررسی)

با یک پنجرهٔ جدید یا حالت ناشناس (Incognito) هم امتحان کنید:

- [ ] صفحهٔ اصلی باز می‌شود و پیام «هنوز محتوایی اضافه نشده است» دیده می‌شود.
- [ ] به‌عنوان مدیر وارد شوید ← پنل مدیریت ← همهٔ بخش‌ها بدون خطا باز می‌شوند.
- [ ] با ایمیل دیگری به‌عنوان مربی ثبت‌نام کنید؛ پیام «در انتظار تأیید» دیده شود و مربی نتواند محتوا بسازد.
- [ ] در پنل ← کاربران، آن مربی را «تأیید» کنید؛ حالا باید بتواند «افزودن محتوا» را ببیند.
- [ ] یک محتوای آزمایشی بسازید (متن + یک PDF + یک لینک)، و یک فایل صوتی آماده را بارگذاری و پخش کنید.
- [ ] در حالت ناشناس: محتوا دیده می‌شود، فایل دانلود می‌شود، امتیاز ثبت می‌شود.
- [ ] در حالت ناشناس: آدرس `#/admin` را باز کنید؛ باید «دسترسی ندارید» ببینید.
- [ ] محتوای آزمایشی را حذف کنید، از «سطل زباله» بازیابی و در پایان برای همیشه حذف کنید.

## ۷. افزودن محتوا و دسته‌بندی

- **محتوا**: وارد شوید ← «افزودن محتوا». عنوان، نوع، دسته‌ها (چندتایی)، متن، فایل‌ها (با توضیح برای هر فایل) و لینک‌ها را پر کنید. «انتشار فوری» پیش‌فرض است؛ برای پیش‌نویس گزینهٔ دوم را بزنید.
- **ویرایش/حذف**: در «محتواهای من» (مربی) یا «پنل مدیریت ← محتواها» (مدیر). حذف همیشه «حذف نرم» است و به سطل زباله می‌رود.
- **دسته‌بندی**: پنل مدیریت ← دسته‌بندی‌ها. افزودن دستهٔ اصلی یا زیرمجموعه، ویرایش نام، جابه‌جایی با ▲▼، غیرفعال‌کردن و حذف.
  - هنگام حذف دسته، فقط ارتباط محتوا با همان دسته پاک می‌شود. اگر محتوایی فقط در همان دسته بوده، پیش از حذف تعدادشان به شما اعلام می‌شود و پس از تأیید به سطل زباله می‌روند. دسته‌ای که زیرمجموعه دارد حذف نمی‌شود.
- **جایگزینی فایل**: در ویرایش محتوا ← «جایگزینی فایل». فایل قدیمی تا زمانی که محتوای دیگری از آن استفاده می‌کند حذف نمی‌شود؛ اگر هیچ‌کس از آن استفاده نکند، در «پنل مدیریت ← فایل‌ها» با برچسب «بدون استفاده» می‌ماند و می‌توانید آن را حذف کنید.

### سطح دسترسی‌ها (خلاصه)
| | بازدیدکننده | مربی تأییدشده | مدیر |
|---|---|---|---|
| دیدن محتوای منتشرشده، دانلود، جست‌وجو، امتیاز خصوصی | ✔ | ✔ | ✔ |
| ساخت محتوا | ✘ | ✔ | ✔ |
| ویرایش و حذف نرم | ✘ | فقط محتوای خودش | همه |
| کاربران، دسته‌ها، بازخوردها، گزارش‌ها، سطل زباله، حذف دائمی | ✘ | ✘ | ✔ |

## ۸. پشتیبان‌گیری

دو بخش جداگانه وجود دارد و **هر دو** باید پشتیبان‌گیری شوند:

**الف) پایگاه داده (متن‌ها، دسته‌ها، کاربران، بازخوردها):**
- ساده‌ترین راه: پنل مدیریت ← **پشتیبان‌گیری** ← «دریافت فایل پشتیبان». یک فایل JSON خوانا دریافت می‌کنید. فایل را در جای امن (و نه GitHub عمومی) نگه دارید؛ ایمیل کاربران در آن است.
- این فایل «نسخهٔ نجات اطلاعات» است، اما برای بازگردانی خودکار ساخته نشده است. اگر روزی دیتابیس از بین رفت، اطلاعات خوانا و قابل برگشت‌اند ولی بازگردانی‌شان به کمک یک فرد فنی نیاز دارد.
- برای پشتیبان کامل و قابل بازگردانی، Supabase در طرح‌های پولی پشتیبان روزانه دارد (**Database ← Backups**). در طرح رایگان معمولاً چنین قابلیتی نیست (شرایط ممکن است عوض شده باشد؛ صفحهٔ همین بخش را ببینید). جایگزین: ابزار خط فرمان Supabase با دستور `supabase db dump`؛ این کار فنی است.

**ب) فایل‌های بارگذاری‌شده (Storage):**
- دکمهٔ JSON فقط فهرست و مشخصات فایل‌ها را نگه می‌دارد، نه خود فایل‌ها. فقط ذخیرهٔ آدرس فایل‌ها پشتیبان واقعی نیست.
- روش ساده: در Supabase ← **Storage** ← باکت `content-files` ← دانلود فایل‌های مهم. نام اصلی فایل‌ها در پنل مدیریت ← «فایل‌ها» آمده است (نام ذخیره‌شده در Storage رمزگونه است).
- روش کامل: Supabase برای Storage یک اتصال سازگار با S3 دارد (Storage ← Settings) که با ابزارهایی مثل rclone می‌توان همهٔ فایل‌ها را کپی کرد. این کار هم فنی است.

پیشنهاد: ماهی یک‌بار دکمهٔ JSON را بزنید و فایل‌های جدید را از Storage دانلود کنید.

## ۹. آنچه آزمایش شده و آنچه هنوز باید روی حساب شما بررسی شود

**آزمایش‌شده (روی یک شبیه‌ساز محلی Supabase، با مرورگر واقعی، در موبایل و دسکتاپ):** صفحهٔ اصلی و حالت خالی، منوی موبایل، ورود/خطای ورود، وضعیت «در انتظار تأیید»، فرم ساخت محتوا و اعتبارسنجی، آپلود فایل و رد فایل غیرمجاز، حذف کد مخرب از متن، نمایش فایل/صوت/لینک، بازخورد، جست‌وجو، حذف نرم، بازیابی، حذف دائمی با تأیید تایپی، تب‌های پنل مدیریت و ساخت دسته. خطای جاوااسکریپت مشاهده نشد.

**آزمایش‌نشده — چون به حساب واقعی Supabase دسترسی نداشتم:**
- اجرای واقعی `01_schema.sql` و پذیرفته‌شدن آن توسط Supabase (ممکن است یک خطای تایپی یا سازگاری با نسخهٔ شما پیدا شود؛ اگر خطا دیدید، متن خطا را برای من بفرستید).
- **رفتار واقعی RLS و سیاست‌های Storage.** کدهای امنیتی نوشته شده‌اند، ولی هنوز در برابر دیتابیس واقعی آزمایش نشده‌اند. بخش ۶ همین راهنما (به‌ویژه آزمایش با حالت ناشناس و مربی تأییدنشده) برای همین است.
- ارسال ایمیل تأیید و بازیابی رمز، آپلود واقعی به Storage و پخش PDF/صوت/ویدئو از لینک‌های امضاشده.

## ۱۰. محدودیت‌ها و نکته‌های شناخته‌شده
- **بازخورد خصوصی**: هر مرورگر برای هر محتوا یک امتیاز دارد و سرور تعداد ثبت در دقیقه را محدود می‌کند، اما چون هویتی گرفته نمی‌شود، جلوگیری کامل از سوءاستفادهٔ عمدی ممکن نیست. مدیر می‌تواند هر بازخورد را حذف کند.
- **حجم فایل**: حداکثر ۵۰ مگابایت برای هر فایل. این سقف طرح رایگان Supabase است؛ ویدئوهای حجیم بهتر است در یوتیوب/آپارات قرار گیرند و فقط لینکشان افزوده شود.
- **فضای رایگان Supabase** محدود است و پروژهٔ رایگانِ بدون فعالیت ممکن است متوقف شود؛ شرایط فعلی را در سایت Supabase ببینید.
- **لینک‌های دانلود موقت‌اند** (حدود یک ساعت). این عمدی است تا فایل‌ها فقط از طریق سایت و با سیاست‌های امنیتی در دسترس باشند.
- دستهٔ غیرفعال از بخش «موضوعات» پنهان می‌شود؛ محتوای آن همچنان در کتابخانه و جست‌وجو دیده می‌شود.
- مربی فقط محتوای **خودش** را ویرایش یا حذف نرم می‌کند؛ مدیر همه را.
- ویرایشگر متن عمداً ساده است (پررنگ، مورب، تیتر، فهرست، نقل‌قول، پیوند) و متن چسبانده‌شده به‌صورت متن ساده وارد می‌شود.
- سایت به دو بستهٔ خارجی وابسته است: کتابخانهٔ Supabase از `cdn.jsdelivr.net` و فونت Vazirmatn از Google Fonts. اگر فونت بارگذاری نشود، از فونت‌های سیستم استفاده می‌شود؛ اگر کتابخانهٔ Supabase بارگذاری نشود، پیام راهنما نمایش داده می‌شود.
- ریشهٔ سایت از آدرس‌های `#/…` استفاده می‌کند (مثلاً `…/index.html#/library`) تا روی GitHub Pages بدون تنظیم اضافه کار کند.
